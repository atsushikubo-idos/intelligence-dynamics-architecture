# IDOS Inverse Observability — 同一データ統合パイロット

日付: 2026-11-05。対象: ZIP提供のIDOS既存ソースと、会話内で作成されたv0.6/v0.7/v0.8。

## 結論

**合成ケース360件による、同じ証拠源からの連続的検証は動作した。実在組織での12PDM固有能力、因果構造の発見、未知変数の自動生成は未証明。**

主張可能: 事前に定めた特徴量・モデル候補を用いて、時間順に学習／較正／評価を分け、(i)予測モデルを較正データのみで選び、(ii)追加観測の有用性を学習データから推定し、(iii)モデルの適合性を未使用データで検査した。

主張不可: 新しい内部構造の発見、企業の因果分析、12PDMの直接的な実測、参照系自動生成、実企業での有効性。

## データと条件

- `idos_inverse_observability_v0_6/eventlog_validation.py` の `synthesize(360,seed=71)` で合成した業務イベントを利用。実データ未取得。
- `make_cases()` でケースを復元し、最初のREVIEW時点に入手済みの情報のみ特徴量に使う。
- ケース開始日時順に、学習216件・較正72件・最終評価72件に**固定分割**。対象は最初のREVIEWから案件終了までの時間。
- ベースラインは審査前経過時間。候補は担当者引継ぎ・差戻し・案件数を各々1つ追加したリッジ回帰。学習時に標準化し、較正データのMAEだけで採用するモデルを決める。評価データで選ばない。
- v0.7の観測設計に必要な正規尤度の平均・分散を**学習データから推定**する。ただし仮説は「審査後の所要時間が長い／短い」という**観測可能な結果分類**。引継ぎ・負荷・資料不足といった因果仮説の尤度を学習したわけではない。二値特徴に正規尤度を使うのは粗い近似。
- v0.8では較正データから求めた予測残差σを使用し、最終評価の残差が事前に設定した2モデル（平均0か平均+2σ）のいずれとも合わないかを検査する。統計的には検査対象の残差が独立・同分散の正規分布に従い、全バッチで1つの平均を共有するという**強い仮定**が必要で、現実イベントでは未検証。
- 異常系は最終評価に属する案件の終了イベントだけ72時間遅らせる合成操作。自然発生の未知構造ではない。

## 既存IDO​​Sへの接続境界

- `Reference v1.1` / `MASTER_MAP v1.1` は変更しない。
- 12PDMは観測・記述プロトコル。モデル説明変数の一つ一つを12PDMの各項目と同一視しない。
- 統計的予測残差 ≠ IDOS `Residual`、作業待ち時間 ≠ `Holding`、予測改善 ≠ `Future Updateability`。
- 参照系は `case_review_v1` と記録する。`review_v2` への比較には計測ブリッジが必要。プログラムは参照系を自動変更しない。
- v0.7での観測案は**提案**であり、実施実績ではない。候補は現に記録されている特徴なので、新しい観測能力の実証はまだない。
- 先行するDiscovery Architectureと生成・介入の役割が重なるため、本モジュールは**数値診断アダプター**として独立して保持する。

## 次の判定ゲート

1. 利用が許可された実在イベントログを取得し、ID・時刻・観測時点・比較可能性を確認。
2. データ分割境界で結果を先取りしていないか、アウトカム確定までの時間を考慮してpurged splitで再検査。
3. 二値観測にベルヌーイ尤度を採用し、期待情報利得と実際のBrier改善を比較。観測を新規に取得できなければ「観測設計成功」としない。
4. v0.8の独立正規残差仮定を検査し、時系列依存があればブロック・ブートストラップ等の較正方法に切替。
5. 12PDMは証拠へのリンク付きの任意タグとし、複数の観測者による整合性を確認。
6. 従来手法（標準回帰・プロセスマイニング・active learning）と同一条件で比較。
7. 不適合を新しい構造の発見と呼ばず、候補発生→追加一次証拠→独立検証の後に再評価。

## 再現方法

**フォルダ位置を変更せず**、隣接している v0.6・v0.7・v0.8 ディレクトリを利用する。

```
python idos_inverse_end_to_end_pilot/pipeline.py
cd idos_inverse_end_to_end_pilot && python -m unittest -v
```

このZIP単体でも動くように、必要なv0.6/v0.7/v0.8のコードのコピーを同梱しています。コピーは検証用依存であり、元の成果物を変更しません。
